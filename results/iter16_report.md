## 从模拟器源码里读到的关键规则

1. **`can_attack(u, e)` 只表示攻击动作合法，也就是敌人在视野内，不表示在射程内**。对远处的敌人下攻击令，单位会走过去打。`API_DOC` 原来写成了"can_attack = 在射程内"，Grok 写程序时也被误导了；现在已经改正。
2. **敌人的索敌规则**：攻击移动时，敌人锁定扫描范围内最近的单位；目标还在射程内、或者目标正在打它时，不会换目标。
3. **医疗艇是空中单位**，只有机枪兵、刺蛇、追猎者能打到它；我方对空单位死光，这局必然超时判负。
4. **超时也算输**。峡谷地形上，双方的自爆兵可能隔着悬崖互相够不着，形成僵局。

## g8 = `kb/library/code/general_claude.py` 做什么

1. **医疗艇**：沿用 Grok 的写法，治疗或后撤。
2. **集火分配**：这一步本回合能开火（冷却 < 0.5 秒）、而且射程内有目标的远程和近战单位，都由程序统一分配目标：
   - 选择余地少的单位先挑；
   - 目标优先级 = 敌方输出 ÷ 剩余有效血量，能打出击杀的目标额外乘 1.5；
   - 已经被分配的伤害会记账，避免溢出伤害；
   - 每一枪的伤害考虑护甲和克制加成（掠夺者、追猎者打重甲加成，巨像打轻甲加成）。
3. **近战拦截自爆兵**：沿用 Grok 的写法。
4. **拉扯**：冷却期间，如果我方射程更远、速度不慢，或者速度明显更快，就后撤一步。对近战和远程敌人都适用。
5. **打破僵持**：连续 10 步双方都没掉血，就全军走向最近的、自己打得到的敌人。

## 结论和改动

- 在线默认换成 `WrittenOnlinePolicy` 运行 `general_claude.py`。Grok 的程序保留，在 `_regress.py` 里用 `written_online_grok` 调用。
- 回归检查：`trace --actions-only` 0 / 345 处不同；`gate` 没有任何一局从赢变输。
- 主要提升来自两件事：读懂模拟器规则（`can_attack` 的真实含义、索敌规则），以及逐局追踪输局；更强的写手模型反而是次要的。第十五轮 Grok 的程序之所以只做到 +25，很大一部分原因是接口文档写错了，它只敢在"能打出击杀"时才下攻击令。
- test2–test6 都已用过。下一次最终判断需要生成 test7，并使用新的 id 前缀。
